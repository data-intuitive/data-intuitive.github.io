What this talk is about
Most debates about AI in omics analysis come down to two questions. Can anyone check the code that produced a result? And where is the data processed? The talk answers both, using one example throughout: a trial team asking to rerun a three-year-old single-cell analysis on a new cohort.

What SKALDU is
SKALDU is a platform for omics data analysis. Scientists pick an assay and run a verified analysis themselves, in their own environment: their own servers or their own cloud. It is built on a method Data Intuitive has used in production at top-five pharma companies for eight years, with more than 300 verified modules.

What SKALDU is not
Data Intuitive supplies the technology. It does not run studies, validate analyses, interpret results medically or set decision thresholds. Those stay with the scientist, the sponsor or the institution.

Where analysis code comes from
There are three usual sources. An in-house expert designs, writes and runs the analysis, so reproducibility rests on one person. The community (nf-core, code published with papers, scripts shared between labs) provides tests, containers and versions per module, but no guarantee that a module stays maintained after its author moves on, and no record of which version, parameters and reference data produced a specific result. AI now assists in both routes and makes development faster.

The shared gap
In all three, checks happen by people, not by design. Community code is reviewed by people, sometimes very well, but no system holds every analysis to the same standard. Many people build, each to their own design, while the analysis is in use. AI does not create that gap; it reaches it faster. Checking code you did not write takes more attention than writing it, and under time pressure that check is what gets skipped.
So who wrote it? Maybe your experts. They designed it, wrote it and ran it. Only they could check it, and the one who knew it best left last year. Maybe the community: many builders, and no guarantee it is still maintained. Or, more and more, AI. It writes faster than any of us, and the checking sometimes gets skipped. Most often it is a combination of all three.

Generation is cheap, verification is not
A plain-English request can now produce a working omics analysis. That part is solved and getting cheaper. Trust does not scale the same way. An omics result cannot show its own correctness: a right and a wrong result look the same on screen.

What a tool can and cannot do
No tool can tell whether a result is scientifically correct. A tool can record exactly what produced it: which code, which version, which parameters, which reference data. That record is what lets someone other than the author check a result later.

The gate
An analysis is a chain of modules. Each module must pass the same five checks before any workflow can use it. Defined inputs and outputs, so modules combine without reading their code. Its own tests, so it proves it still does what it says. A container, so its software environment is frozen and behaves the same years later. A registered version, so every result traces back to what produced it. A dossier per result, listing module versions, parameters, reference data, container images and the full dependency tree.

AI and the gate
Data Intuitive builds modules with AI assistance every day. The gate applies in the same way whether a person or a model wrote the code. SKALDU only contains modules that passed it.

Where the boundary sits
The gate produces evidence, not a validated analysis. In a regulated setting the dossier is the material a validation file is built from. The validation itself, the clinical claim and the sign-off stay with the customer, sponsor or institution.

Where omics data goes today
Data lands on an instrument PC or workstation, where little serious analysis happens, so it moves. Usually to one of four places: the vendor's cloud, a CRO or service lab, the organisation's own cluster or cloud, or a hosted analysis platform. Three of those four are a transfer out of the organisation.

Results without raw data
When analysis is outsourced, the agreement often returns results and reports, not the raw data or the exact method. The customer then cannot rerun or re-examine the analysis, and the record of how the result was made stays with the supplier.

What a transfer costs
In pharma and hospitals each transfer needs a data-processing agreement, a cross-border assessment when the platform sits in another jurisdiction, and a legal and security review measured in months. The cost is rarely the licence. It is a review that outlasts the project. Vendor platforms work well inside their range, but a different kit, a second platform or two omics layers in one study fall outside it.
Now the data question. Where is your data stored, and where is it processed? Today the data is stored in one place and processed in another, and control goes with it. To the vendor's cloud, on their terms. To a CRO, where you often get the results back but not the raw data. To a hosted platform, in their jurisdiction. Remember the phone call? Without the raw data, there is nothing to rerun. And in pharma and hospitals every transfer means a data agreement, a cross-border check and a lot of review.

The timeline on the slide
A typical road for a biomarker, from research to a diagnostic in routine use. Discovery takes months to years. Analytical validation takes months, clinical validation up to two years. The quality system and the IVDR file are built once and then maintained. Deployment takes weeks per site, and post-market surveillance never stops. The colours follow the tiers: grey for research, amber for clinical, coral for diagnostics. A medicine runs longer still, typically ten to fifteen years.

Three tiers, one platform
Research (tier 1) is live today: versioned, tested, every run recorded. Clinical use (tier 2) is planned from 2028 at the earliest, adding electronic signatures to 21 CFR Part 11, a reusable validation package, a GxP mode and impact analysis on every change. Diagnostics (tier 3) is open today to health institutions under IVDR Article 5(5), which lets an institution make and use its own in-house test. From 31 December 2030 the institution must also justify why no equivalent CE-marked test meets its patients' needs.

Tier one is where this gets decided
A biomarker takes five to ten years from discovery to routine clinical use; a medicine typically ten to fifteen. In that time tools, reference data, instruments and people all change. Records can be tightened as work moves up the tiers, but they cannot be created afterwards for runs that already happened.

Responsibility
In a trial the sponsor stays accountable. In a diagnostic setting the institution is the manufacturer. Data Intuitive supplies the infrastructure and the evidence.
